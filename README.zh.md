# Totto · 托托

**一个你看得见的 Agent。**

![Totto](assets/v3-totto.svg)

---

## 核心论点

大多数 AI Agent 是**不可见的**。它们是一个文本框，输入问题，返回答案。
你打一段话，某件事发生了，你收到一条回复。你没法知道这个东西是在工作、
在等待、卡住了、还是睡着了 —— 更没法知道它在你不看的时候**在做什么**。

对聊天机器人来说这没问题。对一个**无人值守运行**的 Agent 来说，这不能接受
—— 它要维持一条队列，要在凌晨三点做决定，还要在你回来时把控制权交还给你。
一个看不见的无人值守 Agent 无法被信任，而一个不能被信任的 Agent，不会有人
敢让它独自跑。

Totto 是对这个问题的回答，分成两半，而它们其实是同一件事：

| 一半 | 它回答的问题 |
|---|---|
| **Totto 的脸** | *它还活着吗？在什么状态？* |
| **路由台** | *它在做什么？哪里卡住了，谁在阻塞？* |

两半做的是同一件事：**把不可见的过程变可见。** 脸让 *Agent* 变得可读，
台让 *工作* 变得可读。只发一个，你要么有一个无处可指的吉祥物，
要么有一块背后没有身份的任务板。

这个仓库两者都有。

## 第一部分 — Totto 的脸

**Totto = Trust + Otter + Bot。中文名：托托。**

### 为什么是水獭

因为每一家科技公司都挑了一个捕食者，而我们不想。

默认的吉祥物都是会猎杀的东西：猎鹰、狼、鲨鱼、老虎。这个隐喻是速度和侵略，
是一个关于**夺取**的隐喻。经过十五年之后，它也已经彻底看不见了 ——
一只狼什么也没说，因为每家公司都有一只狼。

水獭在某一个特定的地方不一样，而那一点对我们很重要：
**水獭会抓住东西。** 它们一辈子带着一块心爱的石头；它们仰面躺在水上，
把找到的东西抱着。水流过的时候，它们不比水快 —— 它们在水里**有锚**。

这就是一个 Agent 该有的正确隐喻。不是跑赢信息洪流，
而是**在它流过去的时候抓住那些是真的东西**。水獭是关于留住、不是关于追逐的动物。

第二个理由，不怎么好听：水獭**不具威胁性**。没有人怕水獭。
一家要把可信数据基础设施卖给政府和行业协会的公司，不应该看起来像个捕食者。
应该看起来像一个**不会松手**的东西。

### 设计

画过三版。两版被否掉，否掉的理由比结果更重要。

**v1 —— 一只熊。** 圆脸、大耳、突出的吻部。否决：太通用。它和品牌里任何
其他东西都没有视觉关系，而通用比丑更糟 —— 丑会被记住，通用不会。

**v2 —— 完整的一只水獭。** 全身、尾巴，还举着一块小数据板。否决：
太复杂，撑不过小尺寸。32px 下尾巴糊成一团、数据板变成一个灰块。

**v3 —— 极简的半个头。** 六个元素，尽量用一条连续路径画完。

| # | 元素 | 画法 |
|---|---|---|
| 01 | 头 | 一个椭圆，宽高比 **1.3 : 1** |
| 02 | 眼睛 | 两个实心圆点，会眨 |
| 03 | 鼻子 | 一个倒三角 |
| 04 | 胡须 | 左右各一条短斜线 |
| 05 | 底部 | **直切** —— 半个头，从平面探出来 |
| 06 | 耳朵 | 两只圆耳，**跟头部轮廓连成一体** |

**两个决定定义了它。**

*它是半个头，不是完整的头。* 底部切平让这个标志显得**在场**而不是**被展示**
—— 一个完整的头是一张画，半个头是一次出现。它也顺手给了标志一条天然的基线，
所以在任何承载面上都能坐正，不需要阴影，也不需要外框。

*耳朵是轮廓的一部分。* 它们是同一条连续路径上的凸起，不是贴在上面的独立圆圈。
大尺寸时很微妙，小尺寸时是决定性的：分离的圆圈在低分辨率下会读成**猫耳朵**，
因为两个重叠的轮廓形状会分裂成两团亮斑。连续的耳朵保持成一个剪影。
这就是为什么最终资产是一条 `<path>`，而不是一堆 `<circle>`。

### 为什么这么极简

参考了三个样本 —— **阿里巴巴**、**京东**、**Grok Bot**。三个标志都极端简单，
而三个都是请得起复杂设计师的人做的。这就是信号。

原因不是品味，而是**复杂度在小尺寸下会变成噪点。** 一个十一个元素的标志，
在 256px 下读得对，在 16px 下读出来是一个灰矩形 —— 而 16px 恰恰是标志最常
出现的地方：favicon、通知图标、列表项。

> **设计目标：在 16 × 16 像素下认得出，在 160 × 160 像素下顺眼。**

所有撑不过 16px 测试的东西都被删掉了。剩下的是上面那六个元素。已经没有东西
可以再删了。

完整构造规格（每一个数字，以及为什么是这个数字）见
[`docs/DESIGN.md`](docs/DESIGN.md)。

## 第二部分 — 路由台

**一个单文件的任务路由控制台。零依赖、零构建、零后端。**

打开 [`routing-desk/index.html`](routing-desk/index.html)，得到一块板。
指向 `?data=<url>`，得到一块实时板。

### 为什么不用项目管理工具

项目管理工具建模的是**工作**。任务路由台建模的是**决策**。

在项目管理工具里，任务有一个状态，有意思的问题是*还剩多少*。
在路由台里，任务有一个**负责人**和一个**阻塞项**，有意思的问题是**谁在等谁**。
前者告诉你进度，后者告诉你队列卡在哪、必须由哪个人来推动。

这个区别产生了这块板真正关心的四个字段：

| 字段 | 它回答的问题 |
|---|---|
| **负责人** | 哪一个具体的人或 Agent 负责？ |
| **边界** | 这个负责人明确**不能**做什么？ |
| **被谁阻塞** | 什么必须先发生，这件事才能动？ |
| **下一步** | 下一个具体的、物理的动作是什么？ |

没有**单一**负责人的任务不是任务，是一个愿望。没有**边界**的任务，迟早会被
越界。没有**下一步动作**的任务，任何人都无法开始，包括它的负责人。

### 设计决定

**一个文件。** 整个控制台是一个 `.html`。没有安装、没有构建、没有服务端。
路由台是被人匆匆打开的东西，常常在手机上，常常由一个不是开发者的人打开。
每一个依赖都是那个人和信息之间的一道失败点。

**零外部请求。** 没有 CDN、没有字体 CDN、没有统计。一块会向第三方发请求的板，
在受限网络里用不了 —— 而受限网络恰恰是内部任务板生活的地方。

**JavaScript 执行之前内容就可见。** 所有区块在 HTML 里就渲染出来。JavaScript
只做增强 —— 它过滤、排序、拉取。它从不控制可见性。

> 这条硬规则来自一次具体的失败：一块板用 `IntersectionObserver` + `opacity: 0`
> 做淡入，结果在观察器从未触发时（无头浏览器、慢设备、减少动效模式）
> **整页空白**。最需要看这块板的人，看到的是什么都没有。
>
> **规则：任何内容的初始样式都不能是 `opacity: 0`。动画可以增加可见性，
> 但绝不可以扣留可见性。**

**封闭的状态词表。** 四个状态，不允许自定义：
`BLOCKED` · `READY` · `RUNNING` · `DONE`。自定义状态是一块板变成天书的方式 ——
只要有人加了「评审中（设计）」，另一个人加了「等待反馈」，这块板就不再是一张
共同的图，而变成一本个人日记。四个状态强迫一次决定，因为实践中也没有第五种情况。

**负责人必须是一个具名的人或 Agent。** 不是一个团队，不是一个部门。
`@后端团队` 是问不了问题的，`alice` 可以。

**不完整是可见的。** 缺少 `owner`、`boundary` 或 `next_action` 的任务会渲染成
红色的警告框，而不是悄悄省掉字段。一块隐藏「不完整」的板，是一块会说谎的板。

### 数据格式

```json
{
  "updated": "2026-01-15T09:30:00+08:00",
  "tasks": [
    {
      "id": "T-001",
      "title": "发布 v0.2 API",
      "owner": "alice",
      "boundary": "不得废弃 v0.1 端点 —— 需要另一位负责人签核",
      "status": "RUNNING",
      "blocked_by": [],
      "next_action": "为六个新端点写 OpenAPI 规格",
      "evidence": ""
    }
  ]
}
```

数据来自两处之一：内联的 `<script type="application/json">` 块（可离线），
或 `?data=<url>`（实时板）。

## 它不是什么

- **不是聊天机器人界面。** Totto 是一个标记，不是对话界面。
- **不是项目管理工具。** 没有甘特图、没有工时估算、没有速率。
- **不是多用户系统。** 没有登录、没有权限、没有同步。
- **不是产品。** 一个标记和一个文件，为一个真实的小团队解决了一个真实问题，
  公开是因为这个问题很常见。
